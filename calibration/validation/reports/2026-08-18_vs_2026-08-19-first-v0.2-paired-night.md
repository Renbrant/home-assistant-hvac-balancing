## Metric semantics

Thermal statistics in the primary comparison below use the analyzer 1.2.0
`directional_hvac_active` context only.

That means samples are included only while `hvac_action` is `cooling` or
`heating`.

They must not be confused with `directional`, which summarizes the whole
reconstructed window.

Booster activity uses the authoritative definition:

`effective_percentage > 0`

The logical Home Assistant `fan.*` state is not used to establish booster
runtime.

## What changed operationally

The POST controller does not simply run the boosters harder.

Across all three bedrooms, the POST window shows:

- lower active runtime;
- lower average command during HVAC operation;
- lower equivalent full-speed workload;
- fewer positive-to-positive speed changes while already running;
- shorter typical active episodes;
- more separate ON/OFF episodes.

This distinction matters for noise interpretation.

The controller became **more episodic**, but not more continuously aggressive.
The extra episode count should therefore not be described as increased speed
modulation.

If acoustic busyness becomes a user-facing concern, the first parameters to
investigate should be dwell/minimum-hold/hysteresis behavior rather than making
Base P less effective solely to reduce episode count.

---

## Adaptive I observation

Adaptive I is materially more present in the POST window than in the historical
legacy behavior. That is expected because the Python controller no longer
inherits the legacy reset defect pattern used as evidence in the August 12–18
baseline.

This first pair is useful evidence that the v0.2 controller is operating as a
different control implementation, but it is not sufficient by itself to
calibrate Adaptive I gain or thresholds.

Adaptive tuning should use multiple comparable post-cutover cycles.

---

## Interpretation

The first matched production night supports three conclusions.

### 1. v0.2 did not degrade thermal balancing

All three bedrooms improved in mean directional error while HVAC was actively
conditioning the house.

### 2. The improvement was not purchased with more local booster workload

All three boosters used less active runtime and lower equivalent full-speed
workload in the POST window.

Bed 3 is especially notable: mean HVAC-active directional error improved by
1.19°F while equivalent full-speed workload fell from 2.347 to 1.363 hours.

### 3. The remaining concern is cadence, not proportional aggressiveness

The POST controller produced more separate active episodes but substantially
shorter episodes and fewer speed-to-speed changes while active.

That pattern does not justify reducing Base P at this stage.

---

## Important confounders

This is observational field data, not a controlled laboratory experiment.

Outdoor load, solar load, occupancy, door state, thermostat demand, compressor
runtime and other conditions may differ between nights.

The earlier paired-night inspection also showed more central HVAC active time in
the POST window. Therefore the thermal improvement cannot be attributed solely
to the local controller, and no electrical-energy savings claim should be made
from this pair.

Equivalent full-speed workload only describes commanded booster effort.

---

## Calibration decision

**Do not change Base P or Adaptive I parameters from this first paired night.**

The current evidence favors keeping the production v0.2 controller unchanged
while collecting additional comparable nights.

A tuning change should be considered only after repeated post-cutover evidence
shows one of the following:

- persistent thermal underperformance;
- unnecessary high-command saturation;
- repeated overshoot;
- unacceptable acoustic ON/OFF cadence;
- an Adaptive I response pattern that is consistently too weak or too strong.

If the main complaint becomes frequent ON/OFF cycling while thermal performance
remains good, investigate dwell/minimum-hold/hysteresis as a separate parameter
family before changing Base P.

## Next validation step

Collect multiple unchanged v0.2 nights and analyze them with the same normalizer
and analyzer definitions.

For each comparable period retain:

- HVAC-active directional statistics;
- HVAC-active error bands;
- booster runtime and command level;
- active episode cadence;
- active modulation metrics;
- equivalent full-speed workload;
- central-assist context;
- actual HVAC/booster power where available.

Only after repeated cycles should Issue #6 move from validation into controller
parameter tuning.
